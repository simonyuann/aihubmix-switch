# 架构决策记录(ADR)

## 已定

### ADR-001 治理在隔离 worktree 的 `Z_code_work` 分支执行(2026-11-28,已定)
- 背景:目标要求隔离执行、每批独立 commit;main 保持稳定。
- 决策:`git worktree add governance-wt Z_code_work`(基于 main 5c306a9)。所有治理提交只进 `Z_code_work`。
- 后果:main 与其他分支不受影响;完成后由仓库主人决定是否合回。

### ADR-002 冲突解决基调"以最新为准"(2026-11-28,已定,继承自既有共识)
- 背景:历史分支合并时曾确立"以最新提交为准"。治理中对同一语义的新旧实现,默认保留较新/被维护者持续演进的实现,删除旧实现。
- 决策:凡发现平行实现,保留 canonical(最新且被验证的)实现;如发现"旧实现反而更正确"的证据,升级为待确认。

### ADR-003 验证能力边界与批次降级规则(2026-11-28,已定)
- 背景:本机无 MSVC Build Tools(`vswhere` 无安装、无 cl/link),`cargo check` 的 proc-macro 编译可能失败;JS 侧 tsc/vitest 可全量验证。
- 决策:Rust 侧批次验证依赖实际 cargo 结果;若 cargo 不可用,Rust 重构批次降级为"只读分析+待验证"或推迟,不得无验证提交行为性变更;前端批次用 tsc+vitest 闭环。
- 后果:治理顺序倾向"可验证优先"(T1/T2/T3/T8/T10 先行)。

### ADR-004 文档语言与位置(2026-11-28,已定)
- 决策:治理文档统一放 `docs/governance/`,中文为主(与仓库既有中文文档一致);代码标识符/路径保持原文。

### ADR-005 `*_config.rs` 家族收敛目标形态:"共享引擎 + 每工具薄声明",边界以负面清单钉死(2026-11-28,已定,由 P-ADR-002 升格;决策经仓库主人授权)
- 背景:T5 涉及 14 个文件 ~25K 行。工具间存在真实语义差异(codex 的 auth.json/experimental_bearer_token、gemini 的 .env 受管块、claude 的 config library 等)。
- 决策:
  1. 采纳"统一引擎 + 每工具薄声明"为目标形态,但引擎的能力域**封闭枚举**,仅限四项:家目录定位、路径模板解析、受管块读写(含 jsonc_document)、迁移检测。
  2. **负面清单(引擎不得吸收)**:任何工具特有语义——auth 凭据形态、token 注入、`.env` 受管块之外的配置改写、工具私有的迁移规则。这些留在各工具自己的 config 模块;宁可重复,不做参数黑洞。
  3. 引擎新增能力域需修订本 ADR,不允许以"加一个可选参数"的方式悄悄扩权。
  4. 落地节奏:每工具独立批次,前置条件是该工具的独特语义清单勘察完成;每批迁移后删除旧实现,cargo check + 行为测试闭环。
- 后果:T5 由 `open(验证受限)` 转为 `in-progress(边界已定)`;防止"为统一而统一"压扁语义。

### ADR-006 上游遗留文档:归档至 `docs/upstream-legacy/`(2026-11-28,已定,由 P-ADR-004 升格;决策经仓库主人授权)
- 背景:仓库为 `farion1231/cc-switch` fork;`README_ZH/JA/DE.md` 与根 README 叙事矛盾,`CHANGELOG.md`(842KB)不在发布链路。
- 决策:选项 (a) 归档——四文件移入 `docs/upstream-legacy/` 并附声明 README(41d487a)。不选 (b) 直接删除:文件可能被外部链接引用,归档保留可达性;不选 (c) 留在根目录:矛盾叙事继续污染第一观感。
- 后果:根目录只剩本项目 README;SUPPORT.md 对上游 README_ZH 的引用为绝对 URL,不受影响。CONTRIBUTING.md 英中双份为内部贡献者文档(非上游遗留),保留现状,后续如有贡献者规范调整再单独处理。

### ADR-007 环境变量前缀:冻结现状,`CC_SWITCH_` 为唯一规范前缀(2026-11-28,已定,补记为 P-ADR-005 → 升格;决策经仓库主人授权)
- 背景:三种前缀并存——`CC_SWITCH_` 240 处、`AIHUB_` 19 处、`CCS_` 9 处(src-tauri 勘察)。更名属破坏性变更:用户既有 shell 环境/CI/目录约定会静默失效。
- 决策:
  1. **不更名**(拒绝破坏性变更);三种前缀的既有语义全部原样保留,继续可读。
  2. `CC_SWITCH_` 声明为唯一规范前缀:新环境变量只允许 `CC_SWITCH_*`(与其余 240 处存量、上游惯例一致)。
  3. `AIHUB_*`、`CCS_*` 标记为 legacy 读取:只读不改、不得新增使用点。
  4. 执行口径:决策记录于本文件与 TASKS T14;T14 剩余的 env_resolver 深模块落地时,在其顶部文档注释重申本政策,评审按"新变量只用 `CC_SWITCH_`"把关。
- 后果:T14 尾巴(前缀更名待确认)关闭;消除"新增变量该用哪个前缀"的决策抖动;代价是三前缀并存的表面积长期存在,由 lint/评审守住不再增长。
