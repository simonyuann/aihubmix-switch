# Claude Desktop 中文启动

在首页将 AI 工具切换为 Claude Desktop，点击“中文启动 Claude Desktop”。首次安装补丁前需保存工作，并确认补丁影响。系统随后会请求管理员授权。完成后以当前用户身份启动 Claude，不以管理员身份运行客户端。

安装期间展示后台实际阶段和已经完成的步骤，以及累计耗时和距上次进展的时间。macOS 展示复制、解包、界面文字处理、资源打包、签名、校验和安装替换。macOS 和 Windows 的并行文字处理上报实际完成文件数，macOS 签名上报实际完成项数。百分比只表示当前可计数阶段。

“取消操作”通过本次操作的独立标识发送请求。macOS 在临时副本阶段安全停止并回收本次工作进程和临时目录。开始替换应用后完成当前事务，再停止自动启动。Windows、Linux 就地写入期间延迟停止，完成补丁及完整性信息更新后停止自动启动。在系统授权窗口等待时，用户可直接取消系统授权。失败后界面保留失败阶段，可重新启动重试或在设置中恢复原版。

macOS 运行汉化脚本时禁用 Python 字节码缓存，保证 AIHub 自身的签名资源完整。

通用设置提供语言偏好、手动选择 Claude 程序位置和“恢复原版”。“保留原设置”仅跳过汉化，不会移除已安装的补丁。恢复会核对版本，不使用其他版本的旧备份。重新安装或升级 Claude 后，下次中文启动会重新检查并请求确认。

资源随 AIHub 离线打包，来源为 MIT 项目 [javaht/claude-desktop-zh-cn](https://github.com/javaht/claude-desktop-zh-cn)，固定提交 `fc3fb5e782b933c40dbac89801ec6db36a8c7358`。保留原授权，并增加失败状态、版本关联备份、敏感错误过滤及临时目录清理。补丁不读取或修改服务商密钥、账号认证、模型分组。

- macOS：支持 `/Applications/Claude.app`、用户 Applications 目录及手动指定的应用；需要系统可用的 Python 3.9+。修改应用资源并本地重新签名。
- Windows：识别独立安装版、MSIX 和手动指定的解压版。新版修改 Claude.exe 的 ASAR 哈希，使原签名失效；按用户明确选择保留上游 Cowork 客户端签名校验补丁，并在首次安装前说明。不会默认接管 WindowsApps 所有权；无法获得写权限时中止，提示改用可写的官方安装版。未知 Cowork 二进制布局按失败处理，不宣称成功。
- Linux：支持官方 deb 的资源布局，使用 PolicyKit 图形授权，需要 Python 3。其他安装布局会明确提示不支持。

官方账号界面的中文优先由 Claude 原生语言功能提供。macOS/Windows 汉化主要针对第三方 API 模式；此功能不提供 Claude 登录、订阅或模型权限。

应用仅记录补丁版本、安装位置与文件摘要，不记录账号或脚本原始输出。安装失败可尝试恢复同版本原始文件；系统取消授权、程序不存在、权限不足等情况均不会显示“汉化成功”。
