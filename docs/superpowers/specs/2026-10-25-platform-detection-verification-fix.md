# v0.2.1 安装检测与导入调用验证修复

用户在 Windows、Linux 上反馈已安装的智能体未被检测到，同时导入后的模型请求出现 503。已完成根因排查，用户明确要求修复。

## 修复范围

CLI 探测独立为可按平台测试的模块，读取当前进程 PATH、常见包管理器目录、npm 自定义 prefix 与 nvm/fnm 版本目录。未定位仅表示检测结果未知，不能据此声明软件未安装。导入窗口打开时重新扫描，并保留重新扫描和手动 CLI 路径入口。Windows 与 WSL 的配置范围明确区分，不跨环境写入配置。

导入必须使用本次 Key、所选模型、所选智能体协议进行真实流式工具调用往返验证。测试使用虚拟连接工具，不运行本机工具。验证完整结束后才写入备份及配置；HTTP 失败、流式错误、不完整响应或无工具调用时保留现有配置，显示服务请求 ID。所选模型的存在性与接口格式先校验。兼容 Claude 的协议回退遵循现有兼容服务行为，不因 503 自动切换模型或协议。

导入确认按钮提示会发送少量真实请求，接入记录存储验证时间。既有记录保留并标记尚未通过新版验证，不用配置存在性代替运行时可用性。

## 验证

本地前端 12 项测试、Rust 回归测试、严格 Clippy、类型检查、生产构建；覆盖目录遗漏、手动路径、模型可列出但 HTTP 503 不改配置、SSE 中断与错误、Responses / Chat / Messages 工具往返和 Claude 兼容回退。真实上游的 Responses 和 Chat 工具往返及隔离配置的真实 Pi CLI 已通过，用户现有配置文件哈希未改变。四个平台 CI 均已各自执行 Rust 原生回归测试并通过，生成 v0.2.1 安装包。
