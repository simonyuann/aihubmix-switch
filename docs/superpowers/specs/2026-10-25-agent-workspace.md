## 信息架构

主导航：API、已接入、会话。工具箱放 MCP、Skills、提示词、用量和连接管理等后续能力；未实现的功能不放可点击空壳。首页不罗列智能体品牌，只展示已接入项。添加时打开可搜索的智能体目录，推荐最近使用和检测到的工具；每项说明自动写入或手动接入，CLI 与桌面 App 的检测分开。一次只选择一个工具和一个模型，高级参数默认折叠。

| --- | --- | --- |
| 多智能体与配置管理 | 统一适配目录；按工具原生格式接入，必要时显示手动配置步骤。只改托管字段、自动备份、可还原 | 第一阶段 |
| 统一会话历史 | 读取各工具本地记录，集中搜索、查看来源/项目/时间，阅读与复制原工具恢复命令；默认只读、不迁移原记录 | 第一阶段 |
| Codex CLI 统一续聊历史开关 | 独立于会话浏览页：统一官方与第三方的 provider 历史分组，可选迁入既有历史，迁移前备份、关闭时按账本还原 | 0.3.1 已发布 |
| 连通与模型验证 | 保留两轮工具验证；能力按协议声明，不把模型列表成功当作实际接入成功 | 已有并持续完善 |

| MCP、Skills、提示词 | 工具箱统一管理，按能力同步到指定工具，预览目标路径与差异、保留原文件 | 第二阶段 |

| 自动更新、跨平台 | GitHub Release 签名更新，macOS/Windows/Linux | v0.2.2 |

参考 CC Switch 提交 `de0a235ad6389ce4afa333b472cdee615a3f3987` 的实际能力：Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi、MiniMax Code、Kimi Code、Oh My Pi，以及其新适配项。另补常用 IDE 插件目录与通用 OpenAI/Anthropic 接入说明。市场没有封闭的 agent 名单，因此通过适配器持续扩展，不宣称未验证工具均已自动兼容。

## 第一阶段首批交付

- 增加可搜索智能体目录，优先可用工具；已有四种自动接入保留。
- 新增 Grok Build、Kimi Code、OpenClaw 原生配置适配，沿用真实模型验证、最小字段写入和条件还原。
- 其他工具先提供明确的接入说明和官方入口，标注手动接入；逐批升级为原生适配，不把仅有名称的目录当作自动支持。
- 会话页首批支持 Claude Code、Codex、Pi、Grok Build、Gemini CLI、OpenClaw 的文件记录。OpenCode 的数据库会话与其他复杂格式在其专用读取器完成后加入；界面会显示当前可读取来源。
- 会话读取只在用户打开页面或刷新时发生，限制文件大小、扫描数量、消息数；不上传记录、不执行会话里的命令，不修改原工具数据。未支持格式和读取失败给出来源级提示，避免被当作无会话。
- 继续会话先提供可复制的原工具命令与工作目录；避免 shell 注入，不自动执行不可信 cwd/路径。跨 agent 续接属于独立上下文转换功能，不伪装成原会话恢复。

## Codex CLI 统一续聊历史：范围澄清

2026-10-25 核对 CC Switch 的「统一 Codex 会话历史」开关后确认：此前规划的只读会话页没有覆盖此功能。它解决的是 Codex CLI 自己的历史 / `resume` 列表按供应商分组的问题，不能以本软件能集中查看记录作为完成依据。v0.2.2 不包含该开关；本段范围界定形成于开发初期，该开关及可选旧历史迁移、条件还原现已在 v0.3.1 发布。

参考实现让官方与第三方使用稳定的共享 provider 标识；本项目现有第三方标识为 `csmy`，不能直接改成 `custom` 而不处理既有历史。实施时需单独完成 provider 身份兼容、官方认证与请求目的地保留、JSONL 与 SQLite 索引一致性、备份账本、可选旧历史迁移与条件还原。默认关闭；迁移旧历史需用户主动选择。跨供应商的加密推理内容可能不能解密，不能保证任意旧会话无缝续聊。

入口放在设置的 Codex 高级选项中，避免占用首页。CC Switch 当前文档说明此开关主要针对 CLI；较新的 Codex 桌面版本已可显示各供应商会话，不应让仅使用桌面版的用户误以为必须开启。

参考：[CC Switch 功能指南](https://github.com/farion1231/cc-switch/blob/de0a235ad6389ce4afa333b472cdee615a3f3987/docs/guides/codex-unified-session-history-guide-zh.md)。
