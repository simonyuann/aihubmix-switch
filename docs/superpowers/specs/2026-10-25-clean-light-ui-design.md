# AIHubMix Switch：以 API Key 为中心的简洁接入方案

状态：用户已确认方案；v0.2.0 已按本方案实现，并由 Electron 迁移至 Tauri 2 / Rust，补充 macOS 支持。

## 目标

操作极致简单，保留注册、申请 API Key、查看 API Key、导入智能体等必要功能。智能体不全部铺在首页。充值后台尚未实现，先占位。采用白色、干净、参考 CC Switch 的桌面工具风格。

## 方案选择

1. 推荐「我的 API 首页 + 按需导入面板」：日常查看、复制、创建和导入集中在 Key 身上，新用户用空状态引导。
2. 纯步骤向导：首次简单，但老用户查看 Key 和重新导入需要重复步骤。
3. 多模块控制台：便于扩展，但当前入口和跳转过多。

## 页面结构

顶部展示品牌，右侧为充值和账户。主导航只有「我的 API」「已接入」两个页签。设置与帮助为次要入口。

### 登录与注册

首次进入提供注册和登录，次要入口为「已有 API Key，直接使用」，允许不登录粘贴接入。注册只收取后端必需字段，邀请码折叠为选填。成功后进入我的 API；没有 Key 时只展示「创建你的第一个 API Key」主操作，已有 Key 时直接展示列表。

### 我的 API

页面右上角提供「创建 API Key」。列表逐行展示名称、脱敏 Key、所属分组和状态。每行主操作为「导入到智能体」，查看、复制和详情为次要操作。配额、用量和创建时间放详情，不把 Key 配额混同于账户钱包余额。

Key 默认脱敏；用户主动查看或复制时才取得完整值，关闭详情或离开页面后隐藏。不将明文加入日志或普通持久化状态。列表需要独立的加载、空状态、请求失败重试和登录过期处理。

### 创建 API Key

一个弹窗选择分组，名称可选并预填「我的 API Key」。显示分组真实平台、描述、倍率和 Claude Code 支持情况；不编造价格或推荐标识。只有一个可用分组时自动选中。

主按钮「创建 API Key」，成功后自动保存并显示「导入到智能体」主按钮，复制为次要操作。创建成功但连接检测失败要单独提示，不能误报为创建失败，避免重试时重复创建。

### 导入到智能体

一个面板完成选择与导入，不层层弹窗：

- 顶部标明本次 Key 的名称与脱敏值。
- 用下拉框选择智能体，只展开所选智能体的配置；Codex、Claude Code、OpenCode、Pi 仅在展开选择器时作为选项出现。
- 只有一个已安装智能体时可预选；多个时首次由用户选择，以后记住上次选择。未安装的仍可选择预配置，并提供安装说明。
- 模型优先复用仍有效的历史选择；只有一个可用模型时自动选中，否则由用户选择。不能把任意第一个模型称为推荐。
- 主按钮直接标明「导入到 Codex」等目标。执行时验证连接、检查必要兼容性、备份并写入，显示进度并防止重复提交。
- 成功后展示所用模型和必要的重启说明，主按钮「完成」，次要操作「继续导入其他智能体」，复用同一 Key。

思考强度、接口格式和路径收在高级设置，保留现有默认值。Claude Code 不兼容时说明原因并提供更换 Key 的入口，不只放一个禁用按钮。

选中或查看另一个 Key 不得改写配置。导入到一个智能体不得自动重写其他智能体。本次操作始终绑定明确的目标 Key 和目标智能体。

### 已接入

只列出用户已接入本服务的智能体，展示名称、模型与可识别的 Key 标识，保留更换配置、还原和详情。空状态引导回我的 API。更换配置显式执行才写入，现有还原确认与备份逻辑保留。

首页移除全部接入和全部还原，用户仍可逐个导入多个智能体。备份目录、配置目录、思考强度与接口兼容选项仍可从设置或详情进入。

### 充值

顶部固定保留「充值」。点击展示「充值功能即将开放」的可关闭面板。当前不显示可提交金额、付款码、支付方式、成功结果或订单记录，不创建虚构支付请求。后台完成后复用同一个入口。

现有 balance 来自当前 Key 的连接检测，不能标为账户钱包余额。含义明确时标为当前 Key 可用额度，未知显示「—」。钱包余额等专用接口支持后再展示。

## 视觉

背景 #f7f8fa，面板 #ffffff，正文 #20242c，次要文字 #667085，边框 #e4e7ec，主色 #2563eb。采用细边框、小圆角、轻微阴影，取消紫色渐变、发光和玻璃效果。全局中文任务文案统一。

主页面、弹窗、原生选择器、提示消息、加载页与 Electron 启动背景都使用浅色。状态用文字和颜色共同表达，键盘焦点可见。检查默认 980 × 780、最小 840 × 640 和更宽窗口，长模型名及路径不能撑破布局。

## 代码依据与边界

已有注册、登录、分组查询、Key 列表、创建以及按 ID 读取完整 Key 的服务能力；查看和复制需补齐受控的 IPC 与 renderer 接口。将原来同时负责账户、创建和列表的 AccountModal 拆为职责明确的组件。

现有程序只保存一个全局当前 Key，connected 判断也与当前 Key 相关。实现时必须调整目标 Key 导入和已接入状态的关系，避免仅切换 Key 就把其他智能体误标为未接入。必要绑定信息不得包含普通存储中的明文 Key。

继续复用配置适配器、安全存储、原子写入和备份还原。不扩展支付后台或智能体安装器。

## 验收

- 新用户能完成注册、创建和导入，无需手动复制粘贴；已有 Key 用户可跳过登录。
- 老用户直接查看、复制或再次导入；首页不平铺全部智能体。
- 创建成功但检测失败时不会引导重复创建。
- 不兼容、未安装、无模型、过期登录与网络错误有明确恢复入口。
- 同一 Key 可逐个导入多个智能体；不同 Key 的选择或查看不改写已有配置，已接入信息与实际配置一致。
- 高级模型配置、备份与还原仍可用；充值占位不误导、不发起付款。
- 运行类型检查、现有测试和生产构建。对新增多 Key 与导入交互补充有针对性的测试，视觉预览使用假数据，避免改写用户真实配置。
