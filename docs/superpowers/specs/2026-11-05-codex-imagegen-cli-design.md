# Codex 命令行生图自动接入

Codex 的第三方聊天配置不会自动成为独立 Python 进程的 OpenAI SDK 环境。软件在现有 Codex `config.toml` 的 `shell_environment_policy.set` 中加入无密钥的 Python 钩子路径；不更改系统环境变量，也不在 Codex 配置中保存生图凭据。配置写入复用客户端文件的写锁、保序补丁、首次备份和崩溃恢复机制。已有显式 `PYTHONPATH` 会保留；如果检测到不兼容的环境过滤、未知配置形状或本软件进程继承了未显式配置的 `PYTHONPATH`，则不写入，并在界面说明调整步骤。

只有执行当前 Codex 目录内的系统 `imagegen/scripts/image_gen.py` 时，Python 钩子才透明地运行本地包装器；不修改该脚本，也不把密钥放到命令行。其他 Python 程序不会获得服务商凭据，已有显式 Python 路径上的 `sitecustomize` 会继续执行。若独立启动的 Codex 继承了本软件进程看不到的其他 `PYTHONPATH`，Codex 配置无法自动保留这个值，需要在 Codex 配置中明确填写原值。包装器每次从当前 Codex 服务商的单条数据库记录读取相配的 API Key 和规范化 `/v1` 地址，清除继承的旧 OpenAI 凭据和地址，只传给此次生图子进程，并遮盖其输出中的密钥。直连和代理路由分别依据设备本地指针和路由状态选择服务商。切换进行中、状态不一致、官方订阅或凭据不完整时拒绝执行。代理启用自动故障转移或聚合模型时无法确定唯一服务商，也拒绝执行。

包装器运行期间监测服务商或密钥变更并停止子进程，但无法撤回已发出的请求。已运行的独立 Desktop 进程可能尚未读取新配置；界面区分配置已写入和进程已生效，要求完全重启 Desktop 并开启新会话。自动接入针对读取该配置的本机 Python 3.11+ 进程，WSL、远程主机、容器，以及 Python 的隔离模式不会自动继承。此功能不改变内置 image_gen 或 Responses 桥接；Codex 是否选择命令行备用方式仍取决于其工具规则和用户请求。

验证使用临时数据库、假密钥和本地模拟 HTTP 端点，覆盖地址规范化、服务商切换、代理路由、更新密钥、官方账号、旧环境清除、故障关闭、输出遮盖、保留现有 Python 配置和无关脚本。可选的端到端测试使用实际 Codex CLI 和模拟 Responses API 调起系统脚本，不调用真实生图接口。
